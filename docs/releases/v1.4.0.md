# 缘分实验室 v1.4.0 正式源码迭代

日期：2026-10-16。范围：Web / 统一后端源码交付；小程序开发源码同时提供。发布状态和固定提交以 [GitHub Release](https://github.com/LYONG1982/destinylab-mvp/releases/tag/v1.4.0) 为准。

## 功能

- 报名与现场活动分别提供入口和二维码，现场可独立主动入场，无需先报名或签到。报名保留六位凭证、邀请函、四站档案及相册。
- 已授权报名和活动资料归入同舟档案，标注来源；管理员管理跟进、签约/服务、相册和昵称个人主页，主页不公开真实姓名和电话。
- 独立活动管理；批量离场、恢复、移除，按活动关闭现场后清零新轮次。报名、已授权同舟档案、照片、跟进与已发布链接保留。
- 运营名单优先、紧凑统计、统一状态和窄屏布局；修复局域网HTTP下crypto.randomUUID不可用导致操作失败。
- 卡牌墙后台提供服务端运行诊断、配置校验、版本冲突保护、未保存草稿、独立模拟预览、保存主屏影响确认。保持四行六列、男女各12席及展示许可规则；预览不写业务数据或抢主控。

## 部署工程师操作

1. 获取v1.4.0标签源码，记录提交哈希。不要使用rc.1历史镜像替代本版；本Release不附新Docker镜像或业务数据库。
2. 备份现有数据库、受保护配置和照片存储，并在独立库验证恢复；沿用正确数据库、活动和会话秘密，避免另建空库。
3. 从同一标签分别构建Dockerfile的 `runner` 与 `migration` 目标。例如Linux amd64：

```sh
git checkout v1.4.0
docker build --platform linux/amd64 --target runner -t destinylab:v1.4.0 .
docker build --platform linux/amd64 --target migration -t destinylab-migrate:v1.4.0 .
```

4. 迁移是独立显式操作，不随应用启动执行。001–013环境补齐014、015；已至014环境执行015；新环境用同版本迁移初始化流程执行001–015。原报名六位凭证转换应沿用live-init中的专用迁移流程，不仅手动拼接SQL。先在恢复库演练，执行时校验 `DESTINY_INIT_DATABASE` 与目标数据库名。详见 [统一档案](../weapp/13-unified-agency.md) 与 [现场管理015](../weapp/14-field-management.md)。
5. 注入服务端受保护环境变量，确认数据库连接串及服务商TLS要求、实际HTTPS根地址、账号哈希与功能开关。数据库凭据、AppSecret、照片、备份不进入源码或镜像。参考 [.env.example](../../.env.example) 和 [部署手册](../../deploy/README.md)。
6. 切换统一应用后检查 `/api/health/live`、`/api/health/ready`，验证两个手机入口、两个后台和两套大屏，再在专用测试活动验收提交、离场/恢复、保存配置与展示同步。勿用真人活动演示清零。

015后的现场轮次和保留照片数据与旧应用不完全兼容；执行过现场清理后不要仅回退旧应用。应停止写入后使用配套旧应用和升级前备份恢复，或向前修复；恢复会丢失备份后的新写入，须安排运维窗口。
