## 建议按此顺序验收

1. 手机扫码，点击“我要报名”。填写昵称、性别、出生年份、城市、联系电话，阅读并勾选报名须知后提交。应出现“报名成功 / 待签到”和专属凭证。刷新后仍可在同一浏览器查看报名；此时大屏现场人数不增加。
2. 点击“完善我的遇见档案”，按生活、期待、相册、完成四站填写；个人相册可上传 JPG、PNG、WebP，每张最多10MB，最多6张，可预览和删除。分站保存并在预览“确认并保存档案”，刷新再次进入，内容应保留。真实姓名、民族及详细生活资料均可不填。
3. 使用现有运营账号登录报名管理。应出现新报名、性别与签到统计；列表联系方式脱敏，点击“查看详情”可见全部报名资料、相册。未选择同舟服务时，机构后台不应出现这份新报名。
4. 手机在相册页主动勾选同舟专业服务并保存。使用现有机构账号登录后应可查看该资料和用户上传相册；工作人员可继续维护备注、签约、服务、公开字段与发布。用户修改资料不会覆盖这些管理字段；为避免旧信息继续对外展示，用户修改后已有宣传页下线，需工作人员核对后重新发布。
5. 运营在详情中输入手机所显示的六位数字签到凭证，点击“核验并签到”；旧截图可切换“使用旧版凭证”输入原16位码。手机回到成功页点击凭证右上角状态区域刷新，再点击“进入活动”。仅此时关联原参与身份或创建一个新身份，随后沿用原答题流程。重复进入不会重复增加人数，原答案保留。
6. 报名配置可在运营列表下方修改标题、日期、地点、说明及“开放新报名”开关。关闭后新用户不能提交，已有用户仍可查看与完善。

## 验收边界

- 手机号目前只作格式校验和活动内防重复，不进行短信验证，也不通过相同手机号自动合并跨设备/跨活动身份。更换设备、清除会话或已取消报名，请工作人员核验处理。
- 报名不自动授权卡牌墙展示，不把出生年份、手机号、收入、住房、家庭和相册写入公共活动数据。卡牌墙继续使用原独立许可；现有互动资料里的年龄段仍由用户在现场流程确认。
- 签到凭证只供核验，不是可登录账号的恢复码。活动重置后需重新签到，不恢复失效参与身份。
- 机构与报名相册同步后，合计最多9张（含机构上传）；超限提示先整理照片。报名照片独立保存，不自动成为大屏头像或公开主页照片。
- 本轮 UAT 没有植入演示报名数据，保留原有参与者、机构会员与相册。自动化测试记录均在独立测试数据库。

## 运维与回退

当前受保护配置与备份在 `~/.config/destinylab/2026-10-12-receipt-six/`：`uat.env`、`uat.pid`、`uat.log`、`before-receipt.dump`、`before-tables.json`、`migration-result.json`。当前构建 `.next-registration-receipt`，上一版 `.next-registration` 和原配置 `~/.config/destinylab/2026-10-12-registration/uat.env` 保留。不要把配置、备份或会话凭据打入交付包。

本轮迁移了2条原报名，全部为六位数字，原16位码完整保存在 legacy_receipt。28张表的非凭证数据摘要迁移前后一致，备份可被 pg_restore 读取。记录与结果见 `verification/registration/receipt-six/uat-result.json`。

部署工程师应先停止报名写入并备份数据库，再加载受保护运行环境：

```sh
DESTINY_MIGRATE_DATABASE=目标数据库名 node --conditions=react-server --import tsx scripts/migrate-registration-receipts.ts
```

该命令要求显式数据库名与 DATABASE_URL 一致，先添加009兼容字段和唯一索引，再以单个事务锁表转换；重复执行不改变已生成的六码。不能只执行009 SQL而遗漏数据转换。首次初始化的 `scripts/live-init.ts` 已包含008、009及转换，随后启动新版应用并检查 `/api/health/ready`。保持 `DESTINY_REGISTRATION_ENABLED=true` 及原共享服务配置。

回退应用时保留兼容字段和全部用户记录，使用上一版构建及对应原配置重启；旧版按数据库当前六码也可核验，但提示仍为16位、无法使用兼容旧码入口。不要删除表或全库恢复覆盖后续报名。功能关闭可设报名开关为false。LAN origin变化需同步配置后重启；公网部署另行完成HTTPS与入口配置。
