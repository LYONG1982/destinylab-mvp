## 1. 已核对的现状

`ScreenApp.tsx` 使用匿名 `screenProjection`，问题 / 在场 / 真实相遇分别按 12 / 8 / 8 秒轮播；10 分钟内至少 3 对愿意认识，才插入 6 秒匿名聚合播报，消费一次。右侧 QR 独立、静止；当前版已有数字与比例轻更新，以及独立双轨迹。数据来自同浏览器的 localStorage / BroadcastChannel 演示适配，没有跨手机实时服务。

现行大屏不输出人物、昵称、头像、地点或辨认码。Participant 没有公开展示授权 / displayMode。真实相遇只统计双方确认已经见面且有 realMeetAt 的关系。参考图中的真人头像、昵称、关系、趋势百分比和“实时数据”不能直接当成现有业务事实。

布局中左侧统计条最大宽度为内容区 80%，二维码占 23%，保留了中央偏右空白；关系场要适应该空白，而不是缩短统计条、移动 QR 或重排三栏。

## 2. 本版建议确认的业务与视觉解释

1. **默认匿名关系场。** 新增的是只读展示适配层和前端类型，不修改 Participant、Invitation 或存储 schema。`PUBLIC / LIGHT / ANONYMOUS` 在显示组件中兼容；当前缺少展示授权时，一律 ANONYMOUS：抽象节点 + “探索者 037”之类临时代号，不显示真实昵称、性别或人物图。
2. **PUBLIC / LIGHT 仅预留兼容。** 后续必须由可信数据源提供明确公开展示依据才启用。开发环境的独立虚构节点可以演示头像 / 昵称 Birth；不能把所有当前参与者默认为同意公开，也不在本次增加授权表单或业务流程。
3. **接受邀请不增加真实相遇数。** MATCH 的“双方愿意认识”阶段表达意愿，继续受原有至少 3 对匿名聚合门槛约束；真实相遇数字仍由 realMeetAt 增长驱动。文案分别是“又有人愿意认识彼此”和“双方已确认见面”，不在意愿阶段宣称已经发生真实见面。
4. **JOIN 不强制加一。** 首次资料完成可触发节点出生，但现有在场统计可能早已包含此人。人数仅平滑到实际投影值；37→38、28→29 都只是变化示例。
5. **按现有空白自适应。** 保持标题、统计条、品牌、页脚、QR 坐标及尺寸。关系场位于文字 / 统计的真实边界与 QR Safe Zone 之间；空间不足时缩小节点、隐藏昵称、聚类，不覆盖文字和二维码。参考图作为层级、气氛和轨迹方向参考，不原样搬入其人物与假趋势。
6. **保留全部现有轮播及隐私策略。** 三个主要场景共享连续背景 / Canvas；原有酒红匿名插播保留其识别方式，使用柔和内容过渡，持续环境层不重建。新增效果不改变业务事件和播报频率。
7. **仍是本地演示。** 保留“演示数据”标识，不换成“实时数据”制造真实接口已接入的印象；不新增 WebSocket / SSE 后端，仅留事件来源接口。

## 4. 关系节点、密度与隐私

- 普通节点近乎静止、低对比；Active 只短暂强调少数有实际行为证据的节点；Highlight 仅用于已允许播出的连接事件。禁止所有昵称和 Halo 同时高亮。
- 单一 motionState：hidden → entering → idle；根据真实视觉事件进入 active / connecting / matched，完成后 idle，离场进入 leaving 后移除。此状态机仅控制显示，不写入业务状态。
- 以 1080p 为基准：1–20 人参考 48–52px，21–50 人 40–44px，51–100 人 32–36px，101–200 人 24–30px。实际屏幕空间优先，4K 按大屏坐标缩放。
- 展示容量根据可用区域和最小间距计算，并设置物理节点硬上限；超量以真实人数聚类，Active / Highlight 优先，绝不铺出 200 个头像和昵称。
- 节点使用当前屏幕会话内稳定的匿名映射，不将持久业务 ID 放入可见标签 / DOM 数据属性。默认投影不带昵称、人物图片或双方原始关系 ID。
- 普通兴趣连线只在真实共同答案有依据且展示策略允许时短暂显示，最多少量同时出现；无证据不随机连线。单对意愿不绕过当前聚合隐私门槛。
- Destiny Trail 为可关闭的低强度附加效果，最多 2–3 个、透明度约 .03 / .06 / .10 的短残影；默认只对少量 Active 节点启用，不形成流星尾巴。

## 5. 事件与跨屏行为

事件均经过展示适配、去重和隐私过滤，示意结构为 `{type, timestamp, payload}`；它是前端事件类型，不增改当前持久化 DomainEvent。数据结果始终由投影负责，动画不能增加人数或真实相遇。

| 事件 / 等级 | 触发依据 | 动效与数据 |
| --- | --- | --- |
| L0 IDLE | 无新行为 | 低密度空气感、极慢节点漂浮；多数节点接近静止。 |
| L1 ANSWER | 既有答案 / 选项计数实际变化 | 对应条形和数字更新，末端一次极小暖金 / 酒红反馈；策略允许时对应匿名节点 Halo 一次。其他场景和节点不重播入场。 |
| L1 ACTIVE | 可核实的近期加入 / 答题等行为 | 只轻强调已有节点，不凭计时器假称用户正在浏览或在线。 |
| L2 JOIN | 在场参与者首次完成基础资料 / 新符合展示条件 | 约 1.5 秒：光点 → 轻 Pulse → 节点 / 经允许的头像 → 代号 / 昵称 → idle。探索人数更新到真实值，不无条件加一。 |
| L3 MATCH / mutual | 已符合既有匿名聚合播报规则的愿意见面关系 | 约 3 秒：Halo → 极细双线 → 中心一次 Pulse → 愿意认识文案 → 淡出。节点不跨屏飞行；附近约 100–150px 环境粒子轻响应。真实相遇数保持实际值。 |
| MATCH / confirmed | 双方确认见面，实际 realMeetAt / 投影计数增长 | 对应轻交汇与确认文案，计数到实际 N+1 或合并后的 N+k；不因动画结束写回业务。 |

- 关系线约 2–4 秒后消失；高频事件按节点 / 统计项合并，最多保留有界短队列；新状态覆盖旧展示，后台不积压回放。
- 本地适配沿用同浏览器 BroadcastChannel；未来 WS / SSE 只替换受控事件来源，不让外部事件绕过展示权限或直接改变计数。
- 首次资料保存成功后，移动端可增加“欢迎进入缘分实验室，也可以看看现场大屏”的轻提示；默认匿名时不承诺公开昵称。资料重编辑不重复出生，不把演示跨标签同步称为已完成跨手机联动。
- mock 方法使用独立虚构节点和显式预览效果，不修改 localStorage 业务数据，不伪造大屏统计或正式事件；真实统计联动仍通过现有演示旅程操作验证。

## 6. 场景与二维码

- QuestionScene：约 1.2–1.8 秒内完成标题、三个选项、比例条和数值进入；后续数据变化只更新受影响内容。比例受分母变化影响时其他条也更新到真实值，微粒反馈只指向实际回答增长的选项。
- ExploreScene：保留现有数字、标题与网络区域；中心轻呼吸，2–3 层环约 5–7 秒缓慢扩散，节点错开低频呼吸。加入触发一次出生 / 波纹，不做雷达扫描。
- MeetingScene：以真实相遇指标为准；只有确实确认见面时增加数字。与愿意认识插播明确区分。
- 各主场景仍按原有时间切换，仅内容层进入退出；背景、环境 Canvas、关系节点和 QR 不因 scene key 被销毁重建。
- QR 图像不缩放、旋转、漂浮、闪烁、改透明度或像素。Safe Zone 至少覆盖整张 QR Card 并留额外边界，粒子、节点、连线、Pulse 和背景事件在绘制 / 布局层同时避开。
- QR 安全矩形只在尺寸 / 布局变化时测量，转换到 Canvas 本地坐标；禁止每帧测量 DOM 边界。

## 7. 性能、降级与稳定性

- 粒子 ≤40；限制 Canvas DPR 与绘制帧率，节点物理对象采用有界池；不逐帧 React setState，不产生无限 DOM / 事件历史。
- 目标设备争取 60fps，至少稳定 30fps；根据实际性能降低粒子 / 物理节点数量，不把桌面结果等同现场设备承诺。
- 只在可见前台驱动 RAF，隐藏 / 离屏 / 卸载后取消 RAF、清理 timer 和订阅；恢复读取当前值，不重播旧事件。
- reduced-motion 下关闭粒子移动、人物漂浮、Ken Burns、轨迹绘制；保留静态节点与可读真实值，必要状态只短淡入或直接切换。
- 避免大面积实时 blur、持续高频布局、Canvas 粒子喷射与高强度光效；采用 transform / opacity 与局部绘制。
