# 移除后允许同一用户重新参与

- 状态：实施及本地验证完成，随本次提交发布。
- 日期：2026-10-26（Asia/Shanghai）。
- 分支：`codex/weapp-release-20261013`；基线 `2f46cf8`。
- 确认依据：已向用户书面说明“保留登录身份，重新建立本次参与记录”、普通离场恢复原资料、移除后重新填写答题、归档和独立档案保留、同步调整 H5/小程序/服务端；用户回复“明确，请实施，并发布到 Github 版本，同步进行调整”。本文件在修改代码前记录该已确认方案和实施步骤，不重复要求确认。

## 目标与范围

1. 普通离场继续调用既有自助恢复，保留原参与编号、资料、答案；行为不变。
2. 从本场移除后，旧现场记录保留受限归档。现场开放时，同一有效 H5 会话或微信身份可主动点击“重新参与”，创建新参与编号，资料和答案重新开始；ready=false，不恢复旧邀请、点位任务或展示授权。
3. 已在场时刷新/重连/登录/GET/小程序回前台不创建新记录；错误界面明确显示“上次参与已结束”，说明需重新填写资料和答题。
4. 报名、同舟档案和既有授权资料不删除、不从旧现场记录复制至新公开资料；微信已验证的报名关联按既有身份规则更新。
5. 同步调整管理端移除说明、产品/旅程/数据/验收/部署文档；提交推送当前 GitHub 分支。不包含云端或微信平台发布。

## 技术方案与预计文件

- 新建专用的重新参与服务和 POST 入口，与保留原记录的 reenter 区分。依据鉴权身份、服务端发出的旧参与编号和轮次处理，只允许该用户自身参与。
- 活动行锁中检查开放状态、当前轮次、旧记录确已移除。复用 dl_commands，以活动/轮次/旧 actor 确定固定操作标识，保存新 actor 关联；并发与重试只能建立一个新记录。旧关联不清除，旧请求不得撤销后续离场/移除或跨轮次重建。
- H5 使用新的活动会话指向新 actor；小程序保持微信 identity 并更新活动参与绑定。对新的前端写请求携带预期 actor，防止旧页内容写入重新建立的参与记录。
- 在受控错误响应中附带本人重新参与上下文，前端按状态展示入口；保留网络失败重试、代际/轮次/版本保护，成功前不跳转。
- 主要模块：`src/server/service.ts`、`wechat-service.ts`、新重新参与服务、H5/mini API 路由、错误响应工具、`src/lib/api/live-client.ts`、`LiveControls.tsx`、小程序 client/欢迎页/互动页、管理端文案。
- 复用已有迁移 001–015；预计无需数据库迁移。若调查发现必须新增结构或改变业务规则，先更新新增范围再确认。

用户追加“还有个变更，就是禁止用户上传自定义头像”，并明确“直接开始实施”。同步关闭 H5 / 小程序头像选择相册、裁剪及上传入口，服务端上传接口拒绝新头像照片；阻止用暂存照片绑定绕过限制。系统头像选择继续可用。独立报名、同舟资料照片保持原功能。用户已明确选择“统一显示系统头像，原照片保留存储”。所有现场参与端、管理端与大屏投影隐藏历史自定义头像，关闭旧头像读取入口；系统头像保存不得删除历史照片。独立报名/同舟照片存储与业务读取不受影响。验证新旧客户端上传拒绝、系统头像保存、独立照片业务回归；随同一版本发布。

## 风险与回退

“移除”不再承担禁止该用户再次参与的语义，本次不新增禁入机制。H5 同一会话不等同于实名用户。新现场资料不会自动接续旧私有表单，已有资料仍保留在原业务域。错误页面不展示他人信息；不能仅删除移除标记或恢复整份活动归档。

无迁移时可回退应用版本以停止新的重新参与入口，已新建的参与记录和原归档保留；不得通过数据库清空回退。
