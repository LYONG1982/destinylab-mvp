## 3. 需要确认的关键业务补充

附件要求真实数据必须明确授权，同时要求不改变原十题流程。建议新增独立可选授权页，而不新增必答步骤：

- Web 新增 `/mobile/member-wall-consent?activity=...`，在现有资料/流程末端增加次要入口。小程序以独立可选面板接入同一业务服务，不改十题顺序、答案或匹配规则。
- 用户预览自己的正反卡，确认公开昵称、虚拟头像、两项标签及三项偏好后主动开启；初始关闭，不默认勾选，不批量回填历史用户。
- 许可记录包含活动、参与者、版本、允许公开的题目范围、启用/撤销时间。说明开关适用于该范围内当前资料，后续改答在许可有效时更新；扩展公开范围必须重新确认。
- 提供“停止在卡牌墙展示”控制。这是本功能独立展示控制，不等同于此前拟移除的“同舟机构资料撤回授权”入口；不顺便修改后者。
- 运营可停用展示，不可代替用户授权；恢复运营状态也不能恢复已撤销的用户许可。
- 真实模式只展示许可有效、在场、资料合格、未被暂停/停用且公开状态明确的参与者。缺少许可/状态未知/删除/离场均拒绝展示。
- 未完成真实许可链路前，真实墙保持空状态；视觉预览可用演示数据，但不得以此宣称真实接入完成。

上述可选授权入口是对附件缺失环节的最小补充，作为本计划范围一并等待用户确认。

## 4. 展示内容与隐私边界

- 新增 PublicMemberCard 白名单 DTO：墙专用公开 ID、遇见码、公开昵称、静态虚拟头像、至多 2 标签、至多 3 项偏好、许可有效标识及必要版本/有效期；不返回内部认证身份、电话、真实姓名字段、联系方式、年龄/性别排序信息、同舟资料或内部备注。
- 公开昵称由用户确认使用昵称，不直接映射同舟 realName；长度先约束为 8 个可见字符并在真实尺寸下验证。明显手机号、邮箱、网址等联系方式拒绝上墙。自动校验不能保证识别所有真实姓名，授权页需清楚提示使用昵称。
- 首版固定题目映射：正面 q3“更愿意先聊”、q5“周末的偏好”；背面 q2“相遇的地方”、q4“关系的节奏”、q8“沟通方式”。只用合法原选项及简短标签；未答不编造，未知选项不展示。
- 遇见码单独生成并持久化，活动内唯一；不复用 invitation.code、pass、会话 token 或内部参与者 ID。码不提供搜索/邀请/读取私密资料能力。
- 强制调用虚拟头像目录，不复用可能返回真实照片的 avatarSource/ParticipantAvatar 路径；即使用户已允许照片上原大屏，本墙也不展示真实照片。
- 后端默认拒绝，前端再次校验；React 文本渲染，不使用 dangerouslySetInnerHTML。昵称与码在卡片几何范围内完整可辨，标签/偏好按行数截断，不能靠无限缩小字体。
- 分别标注参与总人数、已授权且符合展示条件的候选人数、当前屏幕人数；曝光秒数不能命名为观看人数。

## 5. 视觉、布局与预览

路由：`/display/member-wall?activity=...`；独立显式预览 `/display/member-wall/preview`。预览持续显示“演示数据”，与真实接口/统计隔离；服务端模式由运营配置控制，普通访客不能通过 query 写配置或把样例混入真实候选。

先在局部 CSS module 建立 wall token，沿用深酒红、哑金、暖米白及现有字体/品牌资源，不污染根全局样式，不生成新官方 Logo。背景先用纯 CSS 渐变和微弱纹理；P0 不新增动画大依赖，不需要 Three.js。

- 顶部品牌及三类人数，中部严格四行，底部二维码独立区域，CSS Grid/flex 分配尺寸。
- ResizeObserver 测量内容宽高，以卡片高度、宽度、字体和实际容器计算列数，建议限制 3–8 列；1920×1080 先验 4×7，拥挤时改 4×6 并记录证据。
- 低高度/窄屏仍保持四行；无法达到最小可读尺寸时给出“请横屏或使用大屏”的安全提示，不强塞四行微缩文字。
- 正反面严格同尺寸、隐藏背面、身份锚点一致；素材不随两面切换跳动。
- 首批交付 S1 28 人正面、S2 同批背面、S3 8 人加占位；补空状态及断网状态。
- 浏览器全屏需用户点击触发；kiosk 通过浏览器启动配置，网页不宣称可以自动绕过全屏授权。
- 二维码仅使用已配置且有效的真实入口或真实活动小程序码；未配置显示“待配置”，演示页不生成假入口。

## 6. 调度、实时及断网

单一中心调度器与纯状态机，不给每张卡设 interval。时间来自 performance.now/服务端时间锚点，后台挂起不追赶播放积压动画。

默认时间轴：t0 正面；t10 翻背面；t20 翻正面；t30 翻背面；t40 翻正面，整轮翻转完成后再换人。720ms 单卡 + 约 90ms 列错峰，8 列时总时长约 1.35 秒，限制不超过 1.6 秒。
换人默认 25%，可选 50%/100%，数量取整且至少 1；只替换非当前屏幕的候选，候选不足不强换。约 220ms 淡出、替换、320ms 淡入，禁止与翻转叠加。

- 新人只在下一换人周期进入；改答更新本人内容并安全安排在稳定面，撤销/停用/删除收到失效信息即隐藏，优先级高于动画。
- 复用 SSE 订阅活动 revision；收到版本变化先重新验证许可再应用快照，处理乱序/旧请求/断线重连，注销连接、AbortController、observer和timer。
- 另有有界有效期校验：建议真实数据有效期 15 秒，前台 5 秒心跳/校验，SSE失败有退避重试；过期切安全占位。不能用仅连接存活或304延长许可有效期，必须服务端重新检查资格。
- “立即剔除”定义为接收到撤销事件/新快照后立即剔除，不承诺断网时零延迟；断网最迟在有效期到达时清空真实卡片。
- hidden 时停止翻面、换人和曝光计时；恢复先验证当前许可，再回到稳定正面，过期数据不闪现。
- reduced-motion 关闭3D和背景动效，改短交叉淡化或瞬时切换，信息周期保留。

## 7. 公平队列、运营与最小数据扩展

每活动一期一个主展示会话。运营登录后领取短期墙端租约作为主屏；其他窗口可只读镜像，避免多窗口重复累计同一套时长。匿名访问不允许创建展示批次、上报任意成员 ID 或修改配置/统计。公开 API 只返回当前许可有效的展示批次，不提供私密参与者全集。

后端排序：累计实际可见秒数升序 → 最后展示时间升序 → 加入时间升序 → 稳定公开ID。新人时长为零，自然有首次机会，首版不额外给永久优先或敏感属性排序。
曝光通过主屏可见回执计算，带批次、序号、租约和有界时差；服务端只累计实际分配且仍有许可的成员，重复/乱序回执不重复计数。页面隐藏与离线时段不补算。异常关闭最多损失最后一段未确认时长，不编造实际观看量。

拟新增专用表（实施时统一现有命名及索引）：
- dl_member_wall_consents：活动内成员公开码、独立昵称、许可范围/版本/状态/时间。
- dl_member_wall_config：活动配置、模式、翻转/换人周期、比例、列数边界、轮播开关、配置版本。
- dl_member_wall_exposure：累计可见时长、最后展示时间；仅保存可运营的汇总。
- dl_member_wall_sessions：主屏租约、当前分配批次、最后有效回执序号与时间，控制并发和重放。

不新增会员数据库，不修改已有答案/邀请表结构。007迁移只增加本功能对象，既有用户没有许可记录即不展示。给出限定为新增对象的回滚SQL；正常应用回退先关功能并保留新表，删除表需备份及明确数据处置确认。

运营在原后台新增卡牌墙配置：模式、启停、翻面/换人周期、25%/50%/100%、列数界限及主屏状态，校验换人周期至少覆盖完整正反周期；非整倍数配置在首次满足时长的正面稳定点生效。暂停轮播不暂停许可校验及过期清屏。
