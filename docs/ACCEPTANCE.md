# 本地体验验收清单

日期：2026-10-05。技术验证记录见 `verification/2026-10-05-local-validation.md`。下列步骤供用户实际体验；自动化通过不代表用户已经验收。

## 先体验一段完整相遇（约 5–8 分钟）

1. 在同一 Chrome 普通窗口打开 `http://localhost:3210/demo`，选择“从头体验”并确认载入。
2. 分别打开山风、小满、现场运营、现场大屏四个视角。请保留各自标签页。
3. 山风选择“一起逛逛”，查看 42% 同题分布；昵称填山风，选择可以见面，完成剩余五题。推荐有 0–3 人；默认完整场景有 3 人。
4. 选择小满查看共同答案，点击“想认识 TA”并确认发出。山风保持等待；小满页顶部出现邀请入口。
5. 小满点击邀请并选择“我也愿意认识”。两人各自查看相遇任务，主动“确认出发”“我已经到了”。
6. 两人均到达后，山风先点“我已经见到 TA”：运营和大屏仍为 28。小满再确认：两端变为 29；刷新保持 29。
7. 分别选择一起走走、去云影咖啡或自然结束。只保存本人意向；是否一起继续由双方当面决定。
8. 在后台查看双方事实、历史关系及相遇点占用。双方确认见面不自动认定现场已经清空，需工作人员核实后释放相遇点。

如想省去答题，选择“发现同频”后从第 4 步开始。演示角色不会在业务流程中自动换人。

## 异常与恢复

| 操作 | 应看到的结果 |
| --- | --- |
| “没有候选 / 1 位候选 / 2 位候选” | 只显示真实可用数量，1–2 人时明确说明暂时没有更多同频的人 |
| 共同答案页点击“返回推荐列表” | 回到发现页顶部，保留答案、候选和邀请，不触发换一批 |
| 已有待回应邀请时查看另一人共同答案 | “想认识 TA”禁用且解释原因，可点击“查看当前邀请”；原邀请结束后说明消失 |
| 相遇进行中或已完成时返回共同答案页 | 提供对应相遇任务 / 下一站入口，不替参与者完成任何状态 |
| “我想先看看” | 可浏览，发邀请前须主动准备见面；本人不被推荐 |
| “邀请待回应”，在小满页暂不见面 | 山风看到中性结果，可返回探索 |
| 山风等待中撤回 | 关系结束，小满不能继续接受 |
| “邀请待回应”，时间前进 16 分钟 | 邀请过期，无相遇计数 |
| “相遇点忙碌” | 双方保留意愿；运营确认空闲后分配地点 |
| “一方已到达 / 一方确认见面” | 不替另一方到达或确认，不增加真实相遇 |
| “需要现场帮助” | 后台待办接单、处理，参与者收到固定回执 |
| 暂停新邀请 | 新邀请被阻止，已有相遇可以继续 |
| 后台暂停云影咖啡推荐 | 下一站不能新选该商户，历史意向保留 |
| “下一次请求失败”，点“本标签继续山风体验”再操作 | 明确显示未提交，重试后只产生一次事实 |
| “模拟慢连接”后开始操作，另标签重置 | 旧请求被拒绝，不写回新场景 |
| 刷新、返回和再进入 | 保留当前标签角色和已保存的事实 |

故障设置只作用当前标签。场景与时间前进影响同源所有标签。重置不清除其他项目存储；二维码地址配置独立保留。

## 大屏与视觉

普通轮播为问题 12 秒、在场 8 秒、真实相遇 8 秒，二维码常驻。选择“聚合播报”后，近 10 分钟三对独立关系在下一轮播边界触发 6 秒匿名插播，同批只播一次。单对关系不触发；四态固定预览不自动播报。

手机检查 320、360、390、393、430px，后台主要检查 1440×1024；后台表格可垂直滚动。大屏检查 1920×1080 与 3840×2160。截图保存在 `verification/screenshots`；正文、按钮与状态均为真实控件，不是原图切片。

二维码默认指向这台电脑的 localhost。已经自动解码校验四态渲染像素；没有完成手机摄像头或现场距离扫码验收。修改 `/demo` 的目标 URL 并不会自动开放局域网服务或增加跨设备同步。

## 延后范围

商户核销、权益码与服务授权按用户最新要求不实现，界面没有相应操作。正式后端、真实身份、跨手机联动、真实商户权益、正式品牌与活动资料、上线均留到下一阶段。
