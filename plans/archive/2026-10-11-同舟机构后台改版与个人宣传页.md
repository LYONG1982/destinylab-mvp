# 同舟机构后台改版、跟进管理与个人宣传页

日期：2026-10-11（Asia/Shanghai）。状态：实施及局域网 UAT 部署已完成，人工业务验收待用户进行。用户在收到修订计划（含建议状态模型）后明确回复“开始实施”。

## 需求与范围

用户要求重做同舟机构后台 UI：精简登录、密码显隐；登录进入用户列表；点击列表以抽屉展示详情，在详情下面填写多行工作人员备注；点击发布生成该用户的个人专属宣传页面；列表页统计男生、女生、签约和服务情况；完成后发布到 UAT。

本轮面向当前真实服务 `/agency/tongzhou`。现有运营后台仍独立，沿用用户已配置的机构账号与密码，不把密码写入计划或源码。现有局域网 UAT 为 `http://192.168.43.70:3216`、活动 meet、数据库 destiny_lan_uat_20261011，当前健康检查通过。公网仍受 0 元新增费用条件限制。

此前“自定义照片默认上屏与资料编辑优化”计划尚未确认；本轮不擅自将照片上屏许可等同于对外宣传许可，也不自动实施此前未明确的撤回入口删除范围。

## 现有实现结论

- `TongzhouAgencyLive.tsx` 同时呈现页头、退出、介绍及登录，登录前冗余信息明显；密码仅支持隐藏。
- 登录后是卡片列表加固定详情区域，20 条分页及姓名/城市查询；未使用抽屉。
- 数据库已有授权填报、机构会话及头像表。机构读取仅限当前活动有效填报；列表手机号脱敏，详情可查看完整字段。
- 缺少机构备注、签约/服务状态、发布记录、公开字段快照和个人专属路由；现有资料中没有独立公开介绍或宣传照片字段。
- 当前已提交授权文本只覆盖机构联系和人工服务，不能把它直接解释为对外宣传许可。
- 当前有 5 秒前台刷新、退出/失效清理和旧响应拦截，改版需保留这些行为，并防止刷新覆盖工作人员未保存的备注。

## 交互与视觉方案

### 1. 登录页

暖白或浅灰背景、居中简洁卡片，仅显示“同舟婚恋”、账号、密码、显隐按钮及登录。去掉登录前的活动品牌长介绍、统计、退出按钮和资料用途段落。必要的字段标签、正在登录、错误反馈保留。密码默认隐藏，切换不清空输入；支持回车与浏览器密码管理，登录成功清空密码。

### 2. 列表首页

登录后直接进入“用户资料”。顶部为机构名称、当前活动、退出。统计卡展示有效资料总数、男生数、女生数、签约数量及服务状态数量；以当前活动全部有效资料为口径，不只统计当前 20 条。筛选后另外显示匹配条数，避免总量和筛选量混淆。

列表列：姓名、性别、年龄（按出生年份估算）、城市、脱敏手机号、签约状态、服务状态、发布状态、更新时间。支持姓名/城市搜索，性别、签约、服务筛选及分页。没有数据时只显示简短空状态。桌面使用表格，窄屏使用适合点按的行卡片。

### 3. 详情抽屉

点击行从右侧展开，桌面宽度约 560–640px，手机近全屏。标题为姓名、基本摘要与关闭；主体按基本情况、生活情况、择偶期待分组展示已有字段。详情下方为签约/服务状态和“工作人员备注”多行文本框，建议上限 2000 字，显示保存状态和更新时间。

底部固定“保存跟进”“预览”“发布”。备注按纯文本存储与展示，只能机构后台读写；参与者、大屏和宣传页均不返回备注。关闭或切换记录时对未保存输入提示，轮询不覆盖草稿；版本冲突提示刷新后处理，不静默覆盖另一窗口的修改。抽屉支持 Escape、焦点约束和关闭后焦点返回原行。

### 4. 个人宣传页

为每份资料生成不可顺序猜测的专属路径，例如 `/tongzhou/p/{随机标识}`。发布前提供与最终页面一致的预览，显示即将公开的字段。按用户 2026-10-11 的补充，机构管理员可为每位用户逐项设置哪些业务字段公开；服务端校验可发布字段清单，并按本次选择生成快照。未选字段不会进入公开 API 或页面源码，不仅是界面隐藏；不会直接序列化原始提交或工作人员备注。

详情抽屉增加“宣传页设置”：公开昵称、展示编号、个人介绍和逐字段公开开关。允许设置昵称或编号；未设置昵称时用编号作为页面标题，不回退泄露真实姓名。编号独立于数据库 actor 和专属链接随机标识，自动生成且唯一，允许管理员修改，修改时检查重号。列表增加昵称/编号展示及搜索。

可选公开字段覆盖当前个人填报的业务字段及照片、个人介绍，真实姓名、手机号、联系时段、婚姻、家庭和收入等默认不公开，由管理员明确选择后才纳入预览及发布。新宣传页默认以编号展示，个人字段及照片默认关闭，管理员自行勾选。工作人员备注、签约/服务状态、内部标识和权限元数据不属于可公开字段。未配置照片显示简洁占位；不把系统虚拟头像标注为本人照片。个人介绍独立编辑，不直接复制内部备注。

机构确认已经取得该用户对所选内容和照片的公开许可后执行发布，保存发布操作人、时间、来源资料版本、字段快照及确认记录。原有“提交给机构”的授权不会自动转为公开许可。工作人员应在预览中核实文本没有混入联系方式或其他未授权信息。

发布成功后展示“打开页面”“复制链接”，重复点击不生成重复页面。资料修改不直接推送到已发布页面，需预览并再次发布更新；原资料撤回、删除或失效时，公开页面和图片立即不可读，机构可主动下架。详情抽屉显示“已发布/未发布/待更新”。下架是工作人员的发布管理能力，不自动代表新增用户端撤回入口。

宣传页优先适配手机：照片与展示名、基本信息标签、个人介绍、经确认的择偶信息区、同舟品牌。没有内容的区块不显示；不虚构人物故事、认证标识、学历或职业。专属链接不等于仅受邀者可见，任何持链接者都可访问；默认不提交 sitemap，并设置不索引。

## 数据及接口设计

- 新增增量迁移（预计 `database/004-tongzhou-agency.sql`）：机构跟进表保存 activity、actor、organization、note、签约/服务状态、version 和更新时间；宣传草稿保存公开昵称、唯一展示编号、个人介绍及字段选择；发布表保存随机公开标识、来源版本、已发布字段选择与公开快照、独立照片引用、发布状态与时间；必要操作日志记录机构账号及动作，不在日志复制完整备注/私密资料。
- 新记录默认未签约、未服务、未发布，旧资料无损兼容；原始填报和工作人员跟进分开存储，用户修改填报不会清空备注。
- 当前机构为共享账号，日志只能注明机构账号，不能宣称追溯到具体工作人员；本轮不扩展员工多账号系统。
- 机构接口增加保存跟进、预览、发布/更新、下架，保留既有机构 Cookie、Origin、活动/组织范围校验；运营 Cookie 不能替代机构身份。
- 写入包含版本控制和幂等保护；列表/统计采用同一有效记录规则。已撤回/删除资料不能通过猜 actor 读写或再次发布。
- 公共页面及公共照片仅能读取有效发布快照。照片选定后采用受发布记录控制的专用引用，不开放原私有头像接口；下架/撤回/删除时同时失效，避免 CDN/静态缓存继续提供。既有换头像自动清理逻辑需检查发布引用，防止出现失效照片或保留已删除资料。
- 机构公开资料管理所需照片读取只对有权查看当前资料的机构开放；不能因为照片已在大屏显示就认定已授权外网宣传。
- 不将姓名、手机号、密码、会话令牌放入 URL。文本转义、不渲染自由 HTML；不使用 localStorage 保存机构详情/备注草稿。
