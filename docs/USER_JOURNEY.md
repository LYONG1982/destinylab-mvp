# 用户旅程与页面关系

## 参与者主线

01 回答第一题 → 02 看同题分布 → 03 最小资料和准备状态 → 04 完成 q2–q6 → 05 发现 0–3 人 → 06 共同答案 → 07 发出邀请后等待。

另一位参与者在自己的 07 页面收到邀请，自主选择接受或暂不见面。发起方不会跳成接收方。双方愿意后进入 08 分配相遇点，09 分别确认出发、到达、已经见到 TA。两人均确认后进入 10，各自选择一起走走、去云影咖啡或自然结束。

## 旁路与恢复

- 只看看：仍可探索，不向别人推荐；发邀请前先明确准备见面。
- 返回推荐：共同答案页“返回推荐列表”回到发现页顶部，保留原答案和候选；不是换一批。
- 候选不足：只有 1–2 位时提示已全部展示，可以稍后再来；0 位保留真实空态，不补虚假人卡。
- 等待：可返回发现并从顶部任务条回到当前邀请。浏览其他人的共同答案时，解释为何不能再次邀请，并可就近打开当前邀请；进行中相遇和已见面状态分别引导回任务或下一站。
- 拒绝/撤回/过期：中性结果，主动返回探索；不发送私人原因。
- 无空位：保留双向意愿并等候；后台确认空闲后更新。
- 找不到对方：提交帮助；运营接单、处理后，参与者收到回执。
- 刷新：恢复当前角色与业务事实；数据归属于当前浏览器来源。
- 连接模拟失败：不提交事实，保留原页，可重试。
- 场景重置：旧请求不能写回新场景。

## 运营

总览看人数、邀请和去向 → 待办定位帮助或超时 → 详情核对双方事实 → 接单/处理或结束安排 → 按现场情况确认相遇点空闲。

用户页搜索、筛选、分页、查看 6 道答案和时间线；可暂停推荐、离场及发送固定现场提示。伙伴页只有展示、启停推荐与意向概览。

## 本期收敛

2026-10-05 按用户要求取消核销和服务授权链路。商户页不出现领券、核销或授权 Tab，移动端收尾不出现授权勾选。

## 视觉原则

延续酒红、米白、暖金和秋日鼓楼；标题有文化气质，控件是真实 HTML。没有手机系统假状态栏或底部业务 Tab。低人数、等待、拒绝都保留舒适且可退出的表达。

## 微动画中的连续性

- M01 保存成功后，M02 显示“已加入今晚的答案”及真实比例，环形与数字同步；M03 保留汉字输入与系统头像预览。
- M04 保存成功推进六节点，下一题立即可操作；演示城市回应不制造新事件。
- M05 仍按 0–3 人列表探索；M06 真正相同的两侧答案逐行连接。邀请确认弹层不变；成功提交立即进入 M07，展示层承接短信号，失败保留重试。
- M07 收件人看到“昵称想认识你”和接受 / 暂时不见面的明确选择；发件人等待对方决定。
- M08 以两个独立头像与轨迹轻交汇表达双方愿意；有地点才显示已准备好，按钮“查看见面指引”进入 M09。重进或刷新直接显示最终态。
- M09 仅表达各自实际确认的出发、到达与见面；不根据时间推算位置。双方确认后保持原有自动进入 M10，关系动画停止。
- M10 选择云影咖啡后，显示真实相遇点至已选商户的示意连线；不新增导航、核销或授权。减少动画模式仍可完成所有操作。
