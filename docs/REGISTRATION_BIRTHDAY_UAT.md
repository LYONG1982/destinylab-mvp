# 报名文案、姓名顺序与出生日期：本地 UAT

完成日期：2026-10-13（北京时间）。

## 本轮变更

- 删除“资料已与服务器同步”“以下均为选填，可随时补充”“不必有标准答案，只需要真实表达。”“写给未来的那个人 · 选填”“生活里的你”，正常空闲状态不留占位提示。
- 第一站的“真实姓名”从折叠区移至第一个填写项，仍为选填；公开主页仍使用昵称。
- 初始报名和报名详情维护页使用年、月、日三个选择框。年必填；月日可同时留空，也可完整填写。闰年、每月天数与成年日期由共享逻辑校验，无默认生日。
- 完整生日自动显示星座标签；星座采用产品固定公历月日分界，不作性格推断或配对评分。
- 第四站显示服务器已保存的生日/年份和派生星座。编辑出生日期保存成功直接返回第四站；邀请函不增加完整生日展示。
- 生日草稿保存在当前标签页的 sessionStorage，刷新可恢复；与服务器生日冲突时需明确选择保留草稿或使用已保存日期。只有服务器确认后才能视为保存。

## 数据与部署

新增 `database/011-registration-birth-date.sql`：仅在 `dl_registrations` 增加可空 `birth_date` 文本列，规范格式为 `YYYY-MM-DD`。应用服务端负责严格日期校验。`birthYear` 保留，完整日期和年份在同一事务中检查并保存。

本人报名记录与授权运营详情返回 `birthDate`、派生 `zodiac`；它们不进入共享 `TongzhouProfile` 字段集合、机构资料投影或公开字段白名单。旧请求未传生日且年份未变时保留原生日；旧记录只含年份时保持兼容，月日不补造。`scripts/live-init.ts` 已纳入增量迁移。

主 UAT 构建：`h80uZm7NzE3pssovQw4L0`，构建目录 `.next-registration-birthday-v14`。运行配置与旧报名数据备份位于本机受保护目录 `~/.config/destinylab/2026-10-13-birthday/`；不要将该目录复制到公开材料。

迁移及验收前后，对除新增列外的完整报名记录比较一致：原有 3 条记录均保留。主服务继续运行，本轮隔离测试服务已停止。回退时切回前一 `.next-registration-pass-v13` 构建，保留新增可空列及生日数据，不执行删列。

## 验收入口与步骤

[手机报名 / 邀请函](http://192.168.43.70:3216/mobile/register?activity=meet)

1. 新报名：点击“我要报名”，选择年、月、日，检查自动星座；年份仍可单独填写。
2. 已报名：进入“查看报名详情”补充生日；进入“查看我的遇见档案”检查第一站姓名顺序。
3. 第四站查看已保存生日与星座，点击“编辑出生日期”，保存后应直接返回第四站。
4. 旧标签页请刷新以加载新构建。手机需与 Mac 同一局域网。
