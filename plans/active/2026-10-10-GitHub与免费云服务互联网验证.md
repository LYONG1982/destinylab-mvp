## 1. 目标与架构

GitHub 私有仓库 → Render Free Web Service（一个 Next.js 服务）→ 一个 Render Free PostgreSQL 实例内的两个独立数据库。

手机、后台、大屏使用平台实际分配的同一个 HTTPS origin。GitHub 负责源码版本，访问入口使用 Render 默认域名，不购买域名，不采用 GitHub Pages 承载动态服务。保留现有手机十题旅程、邀请和双方确认、公开许可规则及三幕大屏。

自动化演练使用 `destiny_cloud_test`；真人验收使用新建的 `destiny_uat`。同一应用先连测试库，技术验收通过后切换真人库。业务账号隔离，不能把 activity 或 schema 隔离当成两库隔离。

## 2. 必须先通过的条件

1. **零新增费用**：仅选 Free，不添加支付方式、不充值、不购买、不升级、不启用付费任务或磁盘。先核对账号是否已有支付方式及额度；无法排除自动扣费时不创建服务，也不改动账号其他业务的付款设置。额度耗尽接受暂停，不自动付费续用。
2. **数据库安全连接（计划制定时的基线）**：当时的代码要求公网运行使用 `verify-full`。Render 官方明确内网连接不支持完整证书校验，不能直接沿用该内网路径，也不能将 `rejectUnauthorized` 改为 false。2026-10-14 起，当前源码连接方式已按本计划前述实施更新调整为 `DATABASE_URL` 与驱动默认行为。
3. **本计划提请确认的网络调整**：候选改为 Render 数据库外部连接地址，访问来源仅允许该应用控制台列出的出口 IP 范围；迁移/备份时临时加入执行电脑当前公网 IP 的 /32，操作完移除。此方案与之前“数据库仅内网可达”不同，是有访问限制的外部端点，且平台出口范围可能由多个租户共享，不能宣称应用独占网络。独立强凭据和最小权限仍必须保留。数据库是否启用 TLS、如何校验证书，按服务商支持的 `DATABASE_URL` 参数配置并在目标网络实测；当前应用不再通过独立变量或 CA 文件强制该行为。
4. 新建库应在创建参数中限制来源；若平台只能先采用默认广泛允许，立即关闭外部访问，确认限制生效后才迁移或写入数据。不得在默认 `0.0.0.0/0` 下运行业务。
5. 必须实测 Free 账号的独立建库、建角色、跨库拒绝及可信 TLS。外部连接的证书支持尚未实测，不将官方“传输加密”直接等同于项目 `verify-full` 已通过。
6. 任何条件失败，停止该路线并记录具体阻塞；不自动切换其他供应商、不改为 HTTP 数据层、不开放本机数据库、不购买资源。免费隧道仅作为后续另行明确方案的备选。
