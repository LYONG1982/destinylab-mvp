## 3. 视觉与交互方案

### 状态体系

统一标签字号、内边距、圆角与行高，保持文字可直接理解，不只依靠颜色。运营名单建议正文 14px、标签 12–13px，常用控件高度 36–40px，窄屏触控区域不小于 44px。

| 业务维度 | 文字 | 拟用语义色 |
| --- | --- | --- |
| 报名 | 待签到 | 浅金底、深金字 |
| 报名 | 已签到 | 浅绿底、深绿字 |
| 报名 | 已取消 | 中性灰 |
| 现场 | 在场 | 浅绿底、深绿字 |
| 现场 | 已离场 | 中性灰 |
| 互动阶段 | 暂停推荐、等待处理 | 浅金或中性标签，保持原业务文案 |
| 互动阶段 | 进行中的互动 | 克制的酒红或中性标签，保持原业务文案 |

报名签到、现场在场、互动阶段分别表达，不能将“已签到”等同“在场”。来源仍为现有服务器数据和阶段派生函数。未知状态显示中性占位，不猜测成功。

同步、加载、失败属于请求状态，放在对应列表的提示区；保留旧数据时明确提示未刷新成功，失败保留重试入口。避免反复显示相同错误。

### 操作层级

- 查询使用酒红实心主按钮；刷新使用描边次按钮；重置使用低权重文字按钮。详情仍是轻量行内操作。
- 勾选后显示明确的已选人数和操作工具条；未勾选时简化提示。离场、恢复与移除分组，移除使用危险操作样式。
- 清零继续放在活动管理的数据维护区域，不进入报名工具栏。
- 确认框优先展示“影响 N 人”和“报名与同舟档案保留”，随后展示具体后果；按钮对应“确认离场 / 确认恢复 / 确认移除 / 确认清零”。
- 保留既有预览、活动标识输入、点位清场勾选、幂等、禁用与服务器确认逻辑，不新增快捷绕过方式。

### 窄屏名单

- 保留表格内部横向滚动；对报名与现场名单固定身份列、最右侧操作列，现场勾选列与身份列协同固定。
- 768 像素窗口内控制固定列宽度，至少保留可阅读的中间列空间；长昵称省略但可在详情读取完整内容。
- 固定列使用实色背景、边界阴影及合适层级，避免滚动内容穿透；操作可换行，不压缩成不可识别图标。
- 过窄视口下优先身份与详情可用，必要时降级固定列策略；不得出现固定列互相覆盖或页面整体横向溢出。
- 键盘焦点清晰，Tab 可到达滚动区与行内操作，抽屉和确认框的可达性一起检查。

## 6. 风险与回退

- 固定列在窄屏占位过多、共享 CSS 影响其他端：通过后台作用域、明确列宽和窄屏降级控制。
- 颜色误导业务状态：业务维度分别呈现，保留明确文字，不重算后台状态。
- 确认框简化遗漏业务限制：只调整呈现，逐项核对现有输入、勾选、预览与禁用条件。
- 回退仅撤销本轮 UI 提交并重建前端，不回滚数据库或恢复旧现场规则。
