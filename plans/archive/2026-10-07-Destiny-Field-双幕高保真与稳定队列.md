## 2. 当前事实与需要确认的设计取舍

### 2.1 大头像与队列容量

文档第一幕要求头像 72–88px，同时写“≤10人全部展示且不滚动”。仅10行头像就占720–880px，加入标题、性别、间距、统计及故事文案无法在1080P内舒展排版。第二幕建议6–8行、100–122px行高，验收中的“>10才轮播”也与实际窗口不一致。

**建议本次确认采用“大头像优先”：第一幕每个性别队列5人，第二幕每侧6人；超过实际可见容量才分步轮播。** 10人只保留为文档给出的可见人数上限，不作为实际滚动阈值；底层队列保存全部合资格参与者，不截断为10人。此项为明确提出的规格调整，不能静默实施。

| 1080P参数 | 第一幕 CHOICE | 第二幕 LIVE |
| --- | --- | --- |
| 人物编排 | 三个选择，各含男、女两列 | 男生左侧、女生右侧 |
| 头像直径 | 80px | 96px |
| 昵称字号 | 24px，最多5字 | 28px，最多5字 |

## 3. 视觉与文字

- 标题采用系统合法可用宋体/明朝体回退链，数字采用衬线字体，昵称采用清晰无衬线；不下载未知授权字体。
- 以深酒红、暖黑、暖金营造纵深；三种选择为低饱和雾蓝、暖金、玫瑰酒红。保留少量圆弧、抽象轨迹、微光与柔和雾，不做实心卡片、仪表盘或雷达。
- 使用不含文字、人物、头像、数字、二维码或城市地标的原创背景素材补足秋日景深与地面反射，运行时叠加少量Three动态轨迹和光晕。素材可在确认后用内置imagegen制作；保存为独立新资产，不把整张概念图当成界面背景，不引入外部付费CLI或替换用户头像。
- 第一幕保留题目、三个选项、男/女、头像昵称、各区百分比及人数。故事固定“每个人，都在选择自己舒服的靠近方式。”，按文档淡入/停留/淡出/留空循环。

- 参考图的时钟、英文、性格标签、宣传句、具体男女心形连线不复制。光轨不连接可识别的配对双方。
- QR仅改两行文案为“你呢？”和“扫码加入”。码图载荷、码体、静区、像素、固定锚点及扫码逻辑保留；锁定文案区域尺寸，防止改文字导致码体移动。

## 4. 数据适配与计数

现有领域Participant已有gender/joinedAt；只投影到screen的WorldPlayer，不改数据库或领域类型。性别使用明确字段，不从头像文件名、昵称或照片推断。显示已选合法虚拟头像、活动昵称及临时视觉ID；不引入真实姓名、电话、同舟资料、配对双方或相遇码。

数字永远来自最新快照。视觉事件仅产生反馈，不在UI再次count++。

| 变化 | 数据与反馈 |
| --- | --- |
| 首次答Q1，资料尚未完成 | 正确Field及累计选择人数增加；显示统计+1及轻微背景响应，不捏造头像或性别 |
| 随后完成昵称、性别和头像 | 头像进入正确队列并高亮；不能再次增加Field人数或在场人数 |
| 同一次快照完成首答和资料 | 可以合并成一次“+1→头像高亮→入列” |
| 修改Q1 | 原Field减少、新Field增加，总数不变；搬移原Player，不当作新用户 |
| 重复提交/回答Q2–Q10 | 不增加Q1统计；不重复播放Choice+1 |
| 新增在场/离场/重新在场 | LIVE按present真实变化更新；资料变化不等同在场变化 |
| 匿名历史答案变化 | 可反馈统计，不生成虚假人物 |

LIVE保持现有currentParticipants在场口径，资料未完成者也可能计入；头像只显示资料完整且在场者。数字可大于队列中的人数。available继续复用现有业务资格，不能仅检查ready。

独立Mock的48/58/37继续显示34%/40%/26%，保持总和100%，不复制概念图总和101%的示例。真实/screen使用自身统计。

初次读取、刷新、epoch重置、损坏存储恢复只建立基线，不重播历史。保留匿名mutual_confirmed与meeting_confirmed区分，真实相遇总数仍由realMeetAt决定。

## 5. 持续World与稳定队列

### 保留、重构、退出前两幕的部分

| 分类 | 处理 |
| --- | --- |
| 保留 | WorldClock、唯一主帧循环、Scene生命周期、只读订阅、AnimatedCounter能力、QR、头像资源、MEET及匿名INTERSECTION |
| 重构 | CHOICE/LIVE的排版、文字、DOM人物层、男女队列、事件反馈、模式重排及screen设计变量 |
| 退出前两幕 | WebGL头像、头像随机漂移/吸引排斥运动、原浮动昵称定位、旧LIVE available人数句 |
| 仍用于第三幕 | 现有MEET物理运动、匿名历史轨迹和统计；通过最小位置/显隐交接继续运行 |

建立一个持久DOM PlayerLayer，以player.id为key，人物一直处于同一父容器，通过绝对位置变化重排。不能把Player在六列/两列React容器之间搬移导致重挂。保持共同可见人物身份；因容量不同，窗口外人物柔和退出，不要求两幕可见人数完全相同。

StableQueueController维护六个CHOICE队列和两个LIVE队列。joinedAt用于稳定顺序，视觉ID作同时间排序；姓名/可用状态更新不洗牌。各列独立游标、错峰停留。未满时新人物入空位；已满时旧可见项退出、其余上移一位、新项从底部进入。每个可见窗口全程不超过批准容量，同一ID不重复显示。

CHOICE→LIVE采用一次性FLIP/位置插值，整体约2.2秒；先退Choice统计，再归并男女人物，建立中央人数与叙事。Scene、背景空间保持运行，不整页淡出。进出MEET只做必要的人物位置交接，不出现DOM与WebGL双份头像。

## 6. 新人、状态与事件动画

- 首次入场：标题1–1.4秒，Choice按300/500/700ms错峰；人物0.5–0.7秒柔和进入，昵称稍后出现。跨幕已存在人物不重复首开动画。
- 五种背景响应：Destiny Line、Ripple、Particle Gather、Light Sweep、Ambient Lift；仅在事件到达时选一次，持续1.5–2.5秒，不逐帧随机。
- 正确目标区的+1约1.5秒。具备人物资料时，0.2–0.4秒后高亮头像，临时放大1.08–1.15，停留0.9–1.2秒，再用0.7–1秒归位。昵称保持可读且避开QR。
- LIVE新人入对应性别一侧；只有实际在场增加才显示新增人数反馈。仅完善资料时入列但不重复+1。中央数字0.4–0.6秒局部更新，不回零、不老虎机滚动。
- 建立有界newPlayerEventQueue。5秒内突发按目标Field/性别合并成+N，不把跨区人数合并到错误区域，不连续播放20次完整特效；保留所有数据，允许省略过时视觉反馈。
- available仅外围环呼吸，周期2.8–3.6秒、错峰；头像本体尺寸不变。
- 优先级：INTERSECTION > 新人 > 队列更新 > 情绪文案 > Ambient。INTERSECTION沿用现有6秒暂停恢复语义，暂停队列/重排进度，结束恢复原Mode及剩余时间，不补播陈旧大批特效。
- reduced-motion取消持续人物位移和强光变化，数据即时或轻量淡变；隐藏页暂停、恢复读取最新快照；离开页面清理计时器、动画与监听器。
