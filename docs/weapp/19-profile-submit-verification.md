## 原因与改动

截图中的“选一个本次活动头像吧。”对应未选头像的表单拦截：保存尚未发出，因此不会跳转。此前提示离底部按钮较远，年龄缺失又只依赖服务端拒绝，容易让用户误以为点击无效。没有访问线上实例或将本地检查视为线上版本复现。

1. H5 在保存前统一校验昵称、年龄、性别匹配的头像；按钮旁显示错误摘要，聚焦并滚动到第一个错误项。减少动画时直接定位，输入法组合输入期间不触发保存或抢焦点。
2. 头像标记必选并显示选中说明，选择后清除对应错误。保持主动选择规则，“我想先看看”仍可继续。
3. 保存中显示“正在保存…”，禁止重复提交和同时打开头像编辑；失败在按钮附近提示、保留草稿并允许重试。沿用既有幂等键及页面/身份/轮次响应保护。
4. 头像弹窗将当前已接受快照中的真实头像结果交还表单，避免旧值覆盖；取消不修改草稿，性别冲突要求明确重选。资料页只保留表单内一个编辑入口，其他页面仍有原入口。
5. 每个头像选择器使用独立的单选组名称和帮助/错误 ID，弹窗选择不干扰背景表单。照片上屏许可、后端命令及数据库结构保持原有约定。

## 复验与边界

使用 Node 22.22.1、PostgreSQL 17.11-alpine、本地生产服务 `127.0.0.1:3240`。新建独立 `destinylab_profile_test`，直接执行仓库已有 000–015 SQL 初始化空合成库；既有 `live-init.ts` 的 011 包装检查问题没有纳入本次修复，也没有新迁移或接触其他数据库。

配置需包含 `DESTINY_DATA_MODE=server`、`DESTINY_AVATARS_ENABLED=true`、上述本地服务地址、独立 `_test` 数据库及测试会话密钥。环境文件只放受保护本地目录，不提交仓库。测试配置会拒绝非本地数据库或错误端口。

```sh
DESTINY_PROFILE_TEST_ENV=/受保护路径/test.env npx playwright test --config=playwright.profile.config.ts
DESTINY_DATA_MODE=mock npx playwright test tests/e2e/screen-avatar.spec.ts --grep 'avatar is required'
```

第二条使用项目原有 Playwright 配置启动 3210 演示服务，两种模式分别验证。运行第一条前需在 3240 启动同一已构建应用的服务模式实例。

本地证据位于 `docs/verification/2026-10-26-profile/`，沿用忽略规则，不随源码发布。微信内 H5 真机、实际相册兼容、线上网络和生产部署未执行；本次没有调整小程序资料页。
