## 4. 同舟真实填报与机构后台

### 用户流程

问题页入口 → 自愿填报 → 主动勾选同舟服务授权 → 提交成功回执 → 查看／修改／撤回／删除 → 返回原题。

- 复用现有字段及校验：姓名、手机、性别、出生年份、城市、民族、婚姻状况为现有必填项，其余现有需求字段选填。本轮不额外收集身份证或精确定位。
- 授权默认不勾选，明确机构、联系和服务用途、字段范围及撤回方式；修改资料重新提交时确认授权。
- 只在服务端写入成功后显示成功回执；网络失败保留当前内存输入以供重试，不伪造“已发送”。
- 共享模式替换现有“仅本地保存”的演示文案；Mock 模式保留演示标识及虚构数据能力。
- 继续使用当前活动会话识别本人，不把未核验手机号当成登录凭据。本轮不新增短信验证、微信登录或跨设备找回资料功能。

### 数据与权限

- 同一服务和 PostgreSQL 中新增独立私有填报表，按活动、参与者、机构关联，保存资料、授权版本及时间、记录版本和有效／撤回／删除状态。
- 本人只能管理自己的记录；同舟机构会话只能读授权范围内且仍有效的记录。
- 机构登录与活动运营登录独立，服务端确定机构和角色；登录具有限流、密码散列及有效期会话。凭据通过仓库外受保护配置管理。
- 普通现场运营继续查看原有活动数据，不自动获得婚恋表单内容；真实姓名、电话及表单内容不进入公开大屏、其他用户响应、活动统计快照、URL 或普通日志。
- 使用独立私有提交接口及去重台账，只记必要版本、请求摘要和结果，不在通用命令日志复制完整表单。
- 提交、修改、撤回和删除使用事务、版本检查及幂等控制，避免重试重复提交或旧标签页覆盖新资料。
- 删除清除在线业务资料内容；备份的保留与恢复边界在说明中如实记录，不承诺同步抹除既有备份。

### 机构界面

- `/agency/tongzhou` 提供登录、退出、有效资料列表、姓名／城市搜索、分页及详情。
- 列表手机号脱敏，打开详情后在有效授权范围内显示完整填报资料及授权时间。
- 支持定期刷新和手动刷新；接口每次重新校验授权。撤回、删除、退出或会话失效后清空旧详情，取消过时请求，防止迟到响应重新显示资料。
- 机构先提供查询功能；在线匹配、顾问分配、导出、付费和外部消息通知不在本轮范围内。

## 5. 相册头像交互设计

### 入口与步骤

- 在 M03 完善资料的头像区提供“系统头像”和“上传照片”两个入口，保留现有系统头像供选择。
- 上传步骤：打开系统照片选择器 → 选择一张照片 → 正方形裁剪、拖动缩放并预览圆形效果 → 确认使用 → 保存成功后同步。
- 仅获取用户选中的照片；不请求读取整个相册，不强制打开摄像头。
- 已完善资料的用户在个人头像旁可进入“更换头像”，支持重选照片、换回系统头像以及撤回照片上屏许可；更换头像不重置答题和相遇任务。
- 上传中显示进度或处理中状态；取消、上传失败保留旧头像；保存成功后才替换所有业务展示。
- 上传照片不受系统头像性别分类限制；切换性别时本人照片不被误清空。
- 系统头像继续显示“系统虚拟头像”；上传照片使用“用户上传照片”，不再错误标注为插画，也不宣称完成真人认证。

### 各端展示方案（按统一确认实施）

| 展示位置 | 拟定行为 |
| --- | --- |
| 手机本人、推荐、邀请、相遇卡片 | 使用当前已保存头像，保存前清楚告知其他活动参与者可见 |
| 活动运营后台 | 使用同一头像来源，沿用现有活动查看权限 |
| 现场大屏第一、二幕 | 推荐增加默认关闭的“允许本人照片在现场大屏展示”；未开启时使用保留的系统头像 |
| 现场大屏第三幕配对 | 仍需双方原有配对展示许可；是否使用本人照片另外按各自的照片上屏许可决定 |
| 同舟资料 | 服务授权独立于头像和大屏授权，不自动向机构新增提供照片或十题答案 |

- 更换新照片时重新确认新照片上屏许可，避免旧许可直接覆盖新照片。
- 撤回照片上屏许可后，公共投影和图片接口同时停止提供该照片，大屏切回系统头像；不改变已确认见面统计。
- 无需上传照片也可完成活动主流程。

### 存储与接口方案

- 本期轻量头像采用同一 PostgreSQL 的独立图片表保存服务端处理后的受限小图及所有者、版本、内容类型等元数据；业务参与者仅保存图片引用，不在活动 JSON、普通命令或实时消息中传输 Base64／图片字节。
- 暂定原始选择支持 JPG、PNG、WebP，最多 10 MiB；在客户端裁剪压缩，服务端再次校验真实格式、解码尺寸并重编码为 512×512 静态头像，产物设严格大小上限（目标不超过 200 KiB）。去除 EXIF 等原始元数据，不保存相册原图。
- 手机原生相册能否将 HEIC 转换为可处理格式需真机验证；不能转换时给出明确格式提示，不伪称所有 iPhone 照片已兼容。
- 增加经过身份校验、大小限制、频率限制和同源校验的专用上传接口；客户端不能指定其他用户、任意外部图片 URL 或存储路径。
- 图片访问按当前用途和权限判断：本人／活动内允许查看者／有效照片上屏许可。随机图片标识不代替权限检查，取消授权后旧链接不继续公开原图。
- 所有头像展示经统一解析组件，更新公共投影、配对校验和大屏纹理规则，仅接受服务端签发的站内图片资源；不放开任意 URL。
- 图片下载失败使用系统头像兜底；新图保存前不删除旧图。替换或删除后清理失效图片，未提交的临时上传按明确时限清理。
- 数据库方案降低本轮额外存储服务依赖，但会增加数据库和备份体积；用实际产物大小记录容量。本轮不购买对象存储或启用新收费资源，后续大量图片可另行规划迁移。
