# 双向确认后双方自动显示相遇安排

日期：2026-10-29。开发分支 `codex/weapp-release-20261013`。本轮补齐H5展示缺口，复用既有分配与实时同步；没有改变推荐、双向意愿、520码或点位释放规则。

## 用户体验

一方发出邀请 → 对方点击「确认认识」 → 系统自动分配共同地点和各自相遇码 → 两端自动进入相遇指引 → 直接前往现场。

邀请发起方留在邀请页、推荐页或共同答案页，都能收到本次新成立任务并自动进入。看过安排后主动返回浏览，同一任务不会反复强跳。原邀请链接重新打开时按实际进度恢复；本人已记录相遇则进入自己的下一站。

两人仅各自选择“现在可以见面”仍只代表愿意参与，不代替彼此邀请与接受。网页中的实时同步不等于关闭页面后的微信订阅消息或短信。

## 修复的问题

此前服务器接受邀请后已生成本人码并分配可用地点，但发起方可能留在07邀请页，需要额外点「查看相遇任务」。之前图册测试直接打开男生指引页、四人测试点击查看按钮，所以原通过结果没有覆盖“双方无额外动作自动进入”。本轮移除这些绕行动作并增加专门断言，保留原证据和验证范围。

接受方也通过同一状态导航进入，减少接受回调与实时状态的重复跳转。所有相关导航与任务链接保留activity参数；当前URL活动与快照不一致时不由旧快照发起跳转。

已显示记录仅存于当前标签页的有限浏览器记录与内存后备，按活动、轮次、本人、任务隔离；不写入业务数据库、不视为同意或“我已遇见TA”。浏览器存储不可用时依然能进入指引并在本次页面生命周期内防止重复强跳。

## 资源与历史兼容

- 有资源时直接显示真实Meet编号、后台位置、本人动态码、对方???，不要求再次申请、刷新或确认出发/到达。

- 拒绝、撤回、过期、离场、关闭或暂停不触发虚假成功。本人已记录则保留下一站，另一人不被代填记录。
