# 缘分实验室 Destiny Lab｜Codex 前端实施规范 v1.1

> 项目场景：银川鼓楼步行街城市青年社交 MVP  
> 实施范围：移动端 10 页 + 运营后台 4 页 + 现场大屏 4 态  
> 推荐技术栈：Next.js 15 / React / TypeScript / Tailwind CSS / Framer Motion  
> 文档用途：可直接交给 Codex 生成可运行前端项目，先使用 Mock 数据，后续再接入真实 API。

---

## 1. 实施目标

请实现一个可运行、可演示、可继续研发的高保真前端项目，完整呈现以下业务闭环：

```text
鼓楼自然客流
→ 扫码开始
→ 回答轻量问题
→ 完成最小资料
→ 发现同频用户
→ 查看共同答案
→ 发出/接收邀请
→ 双向确认
→ 前往 Meet01
→ 双方确认真实见面
→ 继续散步 / 商户承接 / 自然结束 / 后续服务授权
```

项目不是婚恋 App 完整产品，不实现私聊、刷卡、积分、支付和复杂 CRM。MVP 只验证“真实相遇”闭环。

---

## 2. 强制业务规则

1. 移动端不保留“发现 / 邀约 / 我的”底部页签，10 页按线性故事线组织。
2. 本场推荐规则为异性推荐：
   - 男生仅推荐女生；
   - 女生仅推荐男生；
   - 页面不再询问“希望认识谁”。
3. 昵称仅允许 1–5 个汉字：
   - 不允许英文、数字、符号、Emoji；
   - 输入时显示 `当前字数 / 5`；
   - 中文输入法组合态结束后再校验。
4. 不要求上传真人头像，统一使用系统默认虚拟头像：
   - 男生和女生各有统一插画体系；
   - 同一用户在所有页面中头像保持一致；
   - 明示“系统默认头像，不代表本人长相”。
5. 推荐结果最多展示 3 人，允许 0–3 人。
6. 不显示“匹配度 87%”，统一使用“有 X 道答案相同”。
7. “双向确认”不等于“真实见面”。只有双方分别点击“已经见到 TA”，才计入真实相遇。
8. 活动通知授权与同舟婚恋服务授权必须分开，不默认勾选。
9. 大屏不展示昵称、头像、精确位置等可识别个人信息。
10. 运营后台现场人员默认不可查看手机号等联系方式。

- 正文文字对比度满足 WCAG 4.5:1；
- 交互区域不小于 48×48px；
- 不能只依赖颜色表达状态；
- 表单有 Label 和错误说明；
- 键盘可操作后台核心控件；
- 图片提供 `alt`；
- 关键状态使用 `aria-live`；
- 页面刷新后，从 localStorage 恢复演示流程状态。

# 14. Mock 与数据契约

请读取 `mock/DL_Mock_Data_v1.1.json`，不要在页面组件中散落硬编码演示数据。

推荐实现：

```ts
const mockApi = {
  getParticipants,
  getRecommendations,
  sendInvitation,
  acceptInvitation,
  assignMeetPoint,
  confirmDeparture,
  confirmArrival,
  confirmRealMeet,
  redeemEncounterCode,
};
```

所有方法先 Promise 模拟 200–500ms 网络延迟。
