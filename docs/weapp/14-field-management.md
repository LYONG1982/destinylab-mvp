# 运营后台活动管理与现场维护（迁移015）

适用源码：`codex/weapp-release-20261013` 的本次活动管理更新。GitHub rc.1 下载包仍是历史版本，不能直接升级到本功能。

## 入口与业务边界

所有地址显式带 `?activity=meet`；不同活动使用自己的 activity 标识和二维码。同一活动的新轮次可复用原地址。

| 入口 | 用途 |
| --- | --- |
| `/mobile/register?activity=meet` | 独立报名、六位遇见码、电子邀请函与私有档案 |
| `/mobile/01-start?activity=meet` | 独立现场互动，无需先报名或签到 |
| `/admin/registrations?activity=meet` | 报名查询、签到、单独取消报名 |
| `/admin/participants?activity=meet` | 现场参与者、勾选、离场、恢复、移除 |
| `/admin/activities?activity=meet` | 活动切换/创建、报名与现场独立开关、二维码、题目与点位、现场清零、操作记录 |
| `/agency/tongzhou?activity=meet` | 同舟档案、来源、相册、跟进、签约/服务、宣传页 |
| `/screen?activity=meet` | 现场主大屏 |
| `/display/member-wall?activity=meet` | 遇见卡牌墙 |

小程序双入口仍为 `pages/registration/index` 与 `pages/encounter/index`。现场使用独立 `POST /api/mini/enter`，注册/签到不是入场条件。微信已验证身份可关联前后两种提交顺序；不按姓名或电话自动合并，也不把私有报名资料直接公开。实际 AppID 未确定，当前交付为代码和本地验证，不包含体验版或微信上架。

## 操作定义

- **标记离场**：保留本场历史；停止该身份的答题、推荐、邀请和实时展示。只有运营人员“恢复入场”可以恢复，刷新/改资料不能绕过。已出发点位保留待工作人员确认的占用。
- **从本场移除**：移除当前有效参与者及关联互动、点位关联、求助和卡牌队列；保留受限归档。批量仅当前页明确选中 ID，最多100人。
- **结束本轮并清零现场**：先关闭现场，生成服务端预览，输入活动标识并确认场地空闲，再原子归档和建立新轮次。清零后仍关闭，需要主动开放；旧页面不自动入场。
- 三种现场操作均不取消报名，不删除同舟资料、已授权照片、跟进、签约/服务和已发布链接。取消报名仍在报名管理中单独办理。
- H5 匿名身份以 Cookie 识别，清除 Cookie 或换浏览器能成为新身份；不宣称实名封禁。多活动继续复用已有运营/机构账号权限模型，不引入多租户授权。

报名页面改为紧凑统计、查询和列表；统计是全活动有效报名、不受筛选影响。加载中/读取失败/空结果分别显示；失败保留旧数据并标记，重试成功才更新同步时间。列表保持手机号脱敏和20条分页。

## 部署顺序

1. 备份数据库并在独立库验证恢复。保管好配置和备份，不放进仓库或发布附件。
2. 当前已完成001–014的环境，在切换应用前执行 `database/015-field-management.sql`。文件自身包含事务，支持重复执行。新安装使用同版本迁移镜像或 `scripts/live-init.ts` 执行001–015。
3. 构建并部署同一提交的统一应用；迁移不在应用启动时自动执行。沿用原数据库、会话秘密和运营/机构账号，避免意外另建空库。
4. 验证报名、活动、后台、机构和大屏入口；先在专用合成活动中验证清理操作。不要对真人活动执行清零演示。

015新增 `dl_field_archives`、`dl_field_actions`、`dl_field_removed`、`dl_agency_retained_photos`，并给 `dl_wechat_participants` 增加轮次。报名/机构原表内容不重写。档案照片在清理事务中复制保存，失败整批回滚。归档含原互动数据，只允许受保护数据库维护，不向公共 API 返回内容。操作记录独立于现场状态，不随清零丢失。

代码回退保留新增表与列，但执行过新现场清理后**不应仅回退旧应用**：旧应用无法识别轮次/移除状态和照片保留引用。应停止写入并恢复升级前数据库与配套旧应用，或向前修复；回退会失去备份之后的新写入，须按运维窗口处理。
