## 3. 小程序后续方向（本轮只记录）

- 用户侧：未来小程序承接扫码进入、十题探索、个人虚拟头像、邀请与双方确认、同舟自愿资料填报。
- 现场运营、同舟资料工作台和现场大屏：保留 Web 形态，通过后续统一服务端与小程序同步。
- 复用对象：题库、展示文案、类型与可移植业务规则；小程序导航、表单、存储、生命周期和动效按目标端适配，不能将浏览器的 DOM/存储实现直接当成正式小程序能力。
- 服务端阶段：正式身份、本人/机构权限、受控资料接口、持久化事务、同舟授权撤回/删除与公共大屏投影；公开端不得接收含真实资料的完整浏览器 Mock 快照。
- 技术候选可评估 React + Taro；尚未锁定框架版本或服务供应商。Taro 官方文档确认其支持 React 与微信小程序，同时组件、API、路由规范与 Web 有差异：[介绍](https://docs.taro.zone/docs/)、[React 使用差异](https://docs.taro.zone/docs/react-overall)。这仅为候选路线，当前 Next.js 依赖和动画不承诺自动兼容。
- 后续发布阶段再核对小程序主体、AppID、名称可用性、适用类目、服务域名、隐私说明和提审要求；本轮不声称已满足发布条件。微信官方文档本次读取未成功，具体平台规则在实际启动该阶段时重新核实。
- 顺序：本地 V1.0 品牌验证 → 单独确认小程序及正式后端计划 → 开发者工具与真机体验验证 → 用户确认后再进入提审/发布。
